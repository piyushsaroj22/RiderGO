# RiderGO Backend API Reference

This reference lists the 59 HTTP routes registered by the current backend route files. All responses are JSON unless a route is explicitly marked as multipart or a raw webhook. Protected routes use the HTTP-only `token` cookie. Known errors use `{ success: false, message }`; uncategorized failures use HTTP `500` with `Internal Server Error`.

| Method | URL       | Auth/type | Middleware | Request | Content type | Success response                                           | Errors                         | Description   |

| `GET`  | `/health` | No        | None       | None    | Any          | `200 { success: true, message: "RiderGO API is running" }` | Generic `500` if handler fails | Health check. |

## General notes

- Request bodies are not comprehensively schema-validated before service calls. See [23-api-validation.md](./23-api-validation.md).
- The route files do not define a separate API version prefix.
- No route for listing Driver appeals, payment history, refunds, payouts, analytics, or direct Admin ride management is registered.
- Exact response fields for large paginated admin/appeal lists are defined by their services/types; this reference does not invent fields beyond those confirmed in the source report.
